[8] COORDINATION FIX (conftest.py)

    The 4 conversation-flow integration tests were failing before W3-4 because
    `Depends(get_service(ConversationService))` in `controllers/conversations.py`
    could not resolve — the test Container built in conftest.py only registered
    repositories, not services.  This was a documented coordination gap in
    W3.2's and W3.3's evidence files; W3.3 explicitly handed it off to W3-4:

      "W3.4 must mirror that registration in the test conftest's Container override."

    Fix applied in tests/conftest.py (test code only, no production change):

        from main.framework.services.conversation_service import ConversationService
        test_container._instances["ConversationService"] = ConversationService(
            conv_repo=test_container._instances["conversation_repo"],
            workflow_repo=test_container._instances["workflow_repo"],
        )

    After this fix, all 4 previously-failing conversation tests now pass.

[9] TEST DESIGN NOTES

    For test_conversation_service.py:

      - The fixture `service` overrides `ConversationService._repo_for` to
        return the MagicMock `conv_repo`.  This is required because the service
        constructs a fresh `ConversationRepository(db=...)` per call when a
        session is passed in; mocking at the repository boundary is achieved by
        replacing the helper, not by mocking SQLAlchemy sessions directly.

      - `mock_db` is a `MagicMock()` configured with sane defaults for
        `db.query(...).filter(...).count()/.delete()/.all()` and
        `db.commit()/add()/refresh()`.  No real Session.

      - `db.refresh.side_effect` is set to populate `execution.id` with a UUID,
        mimicking SQLAlchemy's column-default behaviour during flush.  This is
        the only test-level simulation of ORM behaviour; it does not touch a
        real database.

      - Tests verify `assert_called_once_with(...)` / `assert_called_once()` and
        inspect `call_args.args / call_args.kwargs` to assert the service passed
        the right values to the repository boundary.

      - Error-path tests use `pytest.raises(NotFoundError)` (imported from
        `main.framework.services.exceptions`) to assert the service translates
        "entity not found" into the project-standard service exception.

    For test_session_manager.py:

      - `mock_backend` is a `MagicMock(spec=AgentBackend)` so only the real
        Protocol methods are stubbable.  `create_session` and `cleanup_sessions`
        are `AsyncMock` because `ConvSessionManager` calls them with `await`.

      - `asyncio_mode = "auto"` is set in pyproject.toml — no explicit
        `@pytest.mark.asyncio` decorator needed.

      - Tests cover both happy-path dict caching and the
        backend-failure defensive-logging branch (using pytest's `caplog`).
