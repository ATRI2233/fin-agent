Date: 2026-06-09

Changes Made
------------
Added 6 factory methods to Container class for DI service registration:

1. create_conversation_service()
   - @singleton — ConversationService(conv_repo, workflow_repo)
   - Dependencies: ConversationRepository, WorkflowRepository (from container)

2. create_execution_service()
   - @singleton — ExecutionService(exec_repo)
   - Dependencies: ExecutionRepository (from container)

3. create_workflow_service()
   - @singleton — WorkflowService(workflow_repo, exec_service, registry)
   - Dependencies: WorkflowRepository, ExecutionService (via create_execution_service),
     NodeExecutorRegistry (fresh instance), AgentDispatcher (from container)

4. create_scheduler_service()
   - @singleton — SchedulerService(session_factory, workflow_service)
   - Dependencies: SessionLocal (lazy import), WorkflowService (via create_workflow_service)

5. create_message_processor()
   - @per_execution — returns None (no class exists)
   - message_processor.py exposes standalone async functions, not a class

6. create_conv_session_manager()
   - @singleton — ConvSessionManager(backend)
   - Delegates to existing session_manager property

Design Decisions
----------------
- All service factories use singleton pattern (cached in _instances dict)
- No eager DB connections at container init (lazy imports for SessionLocal)
- MessageProcessor is a no-op placeholder (module has standalone functions)
- ConvSessionManager delegates to existing session_manager property
- Dependency chain: ExecutionService -> WorkflowService -> SchedulerService
