DESIGN NOTES
--------------------------------------------------------------------------------

* `validate_cron_expression` keeps the original regex (no croniter dependency)
  to preserve exact behavior of core/scheduler.py.  `*/N` step syntax is NOT
  supported by the original — neither is it in the new service.
* `get_next_run_times` returns `list[datetime]` (not `list[str]` like the
  original) per the task spec; the iteration pattern is preserved verbatim
  so it still feeds the same data into the in-memory `_workflow_jobs` dict
  (via implicit `str(datetime)` conversion in callers, if any).
* `run_scheduled_workflow` delegates DAG execution to the injected
  `workflow_service.run(workflow_id=, db=, execution_id=)` — the original
  used `engine_factory(...)` directly; that responsibility now lives in
  WorkflowService (W4.10).
* The "job_id in self._scheduler.get_jobs()" line is preserved verbatim
  from the original (a known cosmetic bug — `get_jobs()` returns Job
  objects, not strings — but `replace_existing=True` covers the real case).
